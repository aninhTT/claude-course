# Lesson 6.01: Build Session: Your Top Use Case

## Learn

This lesson is mostly building. You've spent Module 5 thinking, planning, and designing — now it's time to make something real.

A few key tips before you start:

### Start in a Separate Session

Keep your course session clean. Open a **new Claude Code or Cowork session** for building. This way your course progress stays intact and your build session has a focused context.

### Use Plan Mode First

Even though you already have a build plan from Lesson 5.05, start the build session by sharing that plan with Claude in the new session. Ask Claude to review it and confirm the approach before building. Fresh eyes (even AI eyes) on a plan often catch things you missed.

### Build the Happy Path

Get the main flow working first. Don't worry about edge cases, error handling, or polish yet. A working prototype that handles the normal case is worth more than a half-finished build that handles every edge case.

### Test with Real Data

Whenever possible, test with your actual Slack messages, real calendar events, real email. Prototypes that run on real data are dramatically more convincing — and more likely to reveal issues — than ones using made-up inputs.

### Come Back to Share

When you're done building, come back to this course session to describe what you built. Reflecting on the build is part of the learning.

## Practice

Build your #1 use case from the Module 5 plans.

**Step 1:** Open a new Claude Code or Cowork session (separate from this course session).

**Step 2:** Share your build plan with Claude. Ask it to review the plan and confirm the approach.

**Step 3:** Use plan mode to finalize the implementation steps, then build it. Work through the steps one at a time. If something isn't working, iterate — don't abandon.

**Step 4:** Test the build with real data. Does it produce the output you expected? Is the output actually useful?

**Step 5:** Come back to this course session. Describe what you built to Claude here:
- What use case did you build?
- What tool(s) did you use?
- How long did it take?
- Does it work?

**Success criteria:** Built your top use case in a separate session. Tested it with real data. Returned to the course session to describe the result.

## Challenge

Run your use case 3 times with real data. Not the same data — different inputs each time (different days, different channels, different emails, etc.).

After each run, note:
- **What worked** — What part of the output was useful and accurate?
- **What broke** — Did anything fail, produce bad output, or behave unexpectedly?
- **What needs improvement** — What would make the next run better?

Save your notes in `workspace/build-1-notes.md`.

> **Before you're done — Question It:** What did Claude assume? What's missing? What could break?

**Success criteria:** Ran the use case 3 times with different real data. Documented what worked, what broke, and what needs improvement.
